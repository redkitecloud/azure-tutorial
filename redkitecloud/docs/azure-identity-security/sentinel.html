Microsoft Sentinel (SIEM & SOAR)

Microsoft Sentinel is a cloud-native Security Information and Event Management (SIEM) and Security Orchestration, Automation, and Response (SOAR) platform. It collects security data from across your entire organisation — Azure, Microsoft 365, on-premises, and other clouds — correlates it to detect threats, and automates responses. It replaces traditional on-premises SIEM solutions with a scalable, AI-powered cloud alternative.

SIEM vs SOAR

SIEMSOAR
Full nameSecurity Information and Event ManagementSecurity Orchestration, Automation, and Response
What it doesCollect, correlate, and analyse security data to detect threatsAutomate response to detected threats — run playbooks
In SentinelData connectors, analytics rules, incidentsPlaybooks (Logic Apps), automation rules

How Sentinel Works

  1. Collect — Data connectors feed security logs into a Log Analytics workspace
  2. Detect — Analytics rules run queries over ingested data and generate alerts when threats are found
  3. Investigate — Related alerts are grouped into incidents; analysts investigate using entity timelines and attack maps
  4. Respond — Playbooks (Logic Apps) automate responses — block user, isolate VM, notify team
  5. Hunt — Security analysts proactively query data to find hidden threats

Analytics Rules

Analytics rules define when Sentinel creates an alert. Three types:

TypeHow It Works
ScheduledRun a KQL query on a schedule — alert when results match conditions
Microsoft SecurityImport alerts from other Microsoft security products (Defender for Cloud, etc.)
Machine LearningBuilt-in ML models detect anomalies and suspicious behaviour patterns
KQLExample analytics rule — detect multiple failed logins
SigninLogs
| where ResultType != 0                    // Failed sign-ins only
| summarize FailedAttempts = count()
    by UserPrincipalName, bin(TimeGenerated, 10m)
| where FailedAttempts >= 10              // 10+ failures in 10 minutes
| project TimeGenerated, UserPrincipalName, FailedAttempts

Incidents and Alerts

When analytics rules trigger, they create alerts. Related alerts are automatically grouped into incidents — a single incident may represent multiple related alerts about the same attack. Analysts work incidents, not individual alerts.

Each incident has:

  • Severity (High, Medium, Low, Informational)
  • Status (New, Active, Closed)
  • Assigned analyst
  • Entity map — users, IPs, hosts involved
  • Investigation graph — visualise attack progression
  • Comments and evidence timeline

Playbooks (Automated Response)

Playbooks are Logic Apps that automate response actions when incidents or alerts are triggered:

  • Block a user in Entra ID when account compromise is detected
  • Isolate a VM from the network when malware is detected
  • Send a Teams/email notification to the security team
  • Create a ticket in ServiceNow automatically
  • Enrich an alert with threat intelligence from external feeds

Threat Hunting

Proactive security analysts use Sentinel Hunting to write and run KQL queries searching for threats that have not yet triggered alerts — looking for low-and-slow attacks, lateral movement, or unusual patterns that rules might miss.

Pricing

Sentinel pricing has two components:

  • Data ingestion — Pay per GB of data ingested into the Log Analytics workspace
  • Log Analytics — Storage and query costs for the underlying workspace

Commitment tiers (100 GB/day, 200 GB/day, etc.) provide discounts over pay-as-you-go for high-volume ingestion.
