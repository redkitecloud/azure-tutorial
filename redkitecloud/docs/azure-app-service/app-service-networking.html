App Service Networking

By default, App Service apps are internet-accessible. But production apps often need to communicate with private databases, internal APIs, and on-premises systems — and to restrict who can access the app itself. App Service has multiple networking features to control both inbound access (who can reach the app) and outbound access (what the app can reach).

Inbound vs Outbound

App Service networking concerns flow in two directions:

DirectionMeaningFeatures
InboundTraffic coming INTO your app from users or other servicesAccess Restrictions, Private Endpoints, App Service Environment
OutboundTraffic going OUT from your app to databases, APIs, on-premisesVNet Integration, Hybrid Connections, Service Endpoints

Access Restrictions

Access Restrictions are IP-based allow/deny rules for inbound traffic — the App Service equivalent of NSG rules. You can allow only specific IP ranges or Service Tags to reach your app.

Azure CLIRestrict app to only allow Front Door IPs
# Allow only Azure Front Door service tag
az webapp config access-restriction add \
  --name mywebapp-2026 \
  --resource-group myRG \
  --rule-name AllowFrontDoor \
  --action Allow \
  --service-tag AzureFrontDoor.Backend \
  --priority 100

# Deny all other traffic (add deny-all rule at lower priority)
az webapp config access-restriction add \
  --name mywebapp-2026 \
  --resource-group myRG \
  --rule-name DenyAll \
  --action Deny \
  --ip-address 0.0.0.0/0 \
  --priority 200
💡
Common Pattern: Front Door + Access Restrictions Deploy Azure Front Door (for WAF, CDN, global routing) in front of App Service, then use Access Restrictions to only allow traffic from the AzureFrontDoor.Backend service tag. This prevents bypassing Front Door's WAF by directly hitting the App Service URL.

Private Endpoints (Inbound)

A Private Endpoint gives your App Service app a private IP address in your VNet — removing the public internet endpoint. All inbound traffic goes through the private IP only.

  • App is accessible only from within the VNet (or connected networks via VPN/ER)
  • azurewebsites.net public URL still exists but resolves to the private IP via Private DNS
  • Requires Premium v2/v3 or Isolated tier
ℹ️
Private Endpoint vs Access Restrictions Access Restrictions filter IPs at the App Service level — the app still has a public endpoint. Private Endpoint removes the public endpoint entirely and routes through a private IP in your VNet. Private Endpoint provides stronger isolation.

VNet Integration (Outbound)

VNet Integration allows your App Service app to make outbound calls to resources in your VNet — databases, VMs, internal APIs — using their private IPs. The app joins your VNet for outbound traffic only (it does NOT become accessible FROM the VNet through VNet Integration).

What VNet Integration EnablesWhat It Does NOT Do
App can connect to SQL databases in VNetDoes not make app accessible from VNet (use Private Endpoint for that)
App can reach VMs in VNetDoes not block inbound traffic from internet
App can reach on-premises via VPN/ERDoes not give app a VNet IP address
Route all outbound traffic through VNet (with route-all)Does not work on Free/Basic tier
Azure CLIEnable VNet Integration
# Add VNet Integration (app subnet must be delegated to App Service)
az webapp vnet-integration add \
  --name mywebapp-2026 \
  --resource-group myRG \
  --vnet myVNet \
  --subnet app-service-subnet
⚠️
Subnet Must Be Delegated The subnet used for VNet Integration must be delegated to Microsoft.Web/serverFarms and should not contain any other resources. Size it generously — each App Service instance uses one IP from the subnet.

Hybrid Connections

Hybrid Connections allow App Service to reach specific on-premises resources (TCP endpoints) without VPN or ExpressRoute. Uses an outbound relay connection through Azure Service Bus.

  • Install the Hybrid Connection Manager agent on an on-premises server
  • The agent opens an outbound connection to Azure — no inbound firewall rules needed
  • App Service can then reach specific on-premises endpoints (hostname:port)
  • Available on Basic tier and above
  • Not as scalable as VPN — best for specific point-to-point connections

Service Endpoints

Service Endpoints extend VNet identity to Azure services so App Service can access Azure SQL, Storage, etc. over the Microsoft backbone. Less secure than Private Endpoints (service still has a public IP) but simpler to configure.

💡
AZ-104 Exam Tip Know that VNet Integration is OUTBOUND only (app reaches VNet). Private Endpoint is INBOUND only (VNet reaches app, removes public endpoint). Hybrid Connections enable on-premises access without VPN. Access Restrictions are IP-based allow/deny rules. These are frequently confused in exam questions.
