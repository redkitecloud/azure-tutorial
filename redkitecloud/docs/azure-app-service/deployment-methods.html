Azure App Service Deployment Methods

Azure App Service supports multiple deployment methods — from a simple ZIP upload to fully automated CI/CD pipelines that deploy on every Git push. Choosing the right method depends on your team, workflow, and requirements. This page covers every deployment option with practical examples so you can pick the best fit.

Deployment Center

The Deployment Center (App Service → Deployment Center) is the single hub where you connect and manage all deployment sources. From here you configure CI/CD, view deployment history, and troubleshoot failed deployments.

GitHub Actions

The recommended approach for teams using GitHub. When you connect GitHub in Deployment Center, Azure automatically generates a GitHub Actions workflow file in your repository.

  1. App Service → Deployment Center → Source: GitHub
  2. Authorise GitHub, select repository and branch
  3. Azure creates .github/workflows/azure-webapps.yml
  4. Every push to the selected branch triggers build + deploy automatically
GitHub ActionsNode.js deployment workflow
name: Deploy to Azure App Service
on:
  push:
    branches: [main]
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install && npm run build
      - uses: azure/webapps-deploy@v3
        with:
          app-name: mywebapp-2026
          publish-profile: ${{ secrets.AZURE_WEBAPP_PUBLISH_PROFILE }}
          package: ./dist

Azure DevOps Pipelines

For enterprise teams using Azure DevOps — connect Azure Repos or GitHub via Deployment Center with Azure DevOps as the build provider. Supports approval gates, staged releases, and advanced pipeline control.

Local Git

App Service acts as a Git remote — push code directly from your machine to deploy. Good for individual developers or simple setups without a CI/CD system.

Azure CLI + GitConfigure and deploy via Local Git
# Enable local Git and get the remote URL
az webapp deployment source config-local-git \
  --name mywebapp-2026 \
  --resource-group myRG

# Add the App Service as a Git remote
git remote add azure https://mywebapp-2026.scm.azurewebsites.net/mywebapp-2026.git

# Push to deploy
git push azure main

ZIP Deploy

Package your app as a ZIP and deploy via the Azure CLI. Fastest method for scripts and pipelines that don't use GitHub or DevOps.

Azure CLIZIP deploy
az webapp deploy \
  --resource-group myRG \
  --name mywebapp-2026 \
  --src-path myapp.zip \
  --type zip

Container Deployment (ACR)

Deploy a Docker container from Azure Container Registry (ACR), Docker Hub, or any private registry. App Service pulls the image and runs it — you manage only the container image.

Azure CLIDeploy container from ACR
# Create web app from container image
az webapp create \
  --name mywebapp-2026 \
  --resource-group myRG \
  --plan myAppServicePlan \
  --deployment-container-image-name myacr.azurecr.io/myapp:latest

# Enable continuous deployment (auto-redeploy on image update)
az webapp deployment container config \
  --name mywebapp-2026 \
  --resource-group myRG \
  --enable-cd true

App Settings and Connection Strings

App Settings inject environment variables at runtime — use them to store secrets, connection strings, and environment-specific config without hardcoding values in code.

Azure CLISet App Settings
az webapp config appsettings set \
  --name mywebapp-2026 \
  --resource-group myRG \
  --settings \
    NODE_ENV=production \
    API_KEY=@Microsoft.KeyVault(SecretUri=https://myvault.vault.azure.net/secrets/apikey/)
💡
Reference Key Vault Secrets Use the @Microsoft.KeyVault(SecretUri=...) syntax in App Settings to pull secrets directly from Key Vault — they never appear in portal logs or source code.
