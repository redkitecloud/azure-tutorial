Deploying a Web App to Azure App Service

Azure App Service supports many deployment methods — from simple drag-and-drop ZIP uploads to fully automated CI/CD pipelines triggered by Git pushes. Choosing the right deployment method depends on your team size, workflow, and requirements. This page covers every major deployment option with practical examples.

Deployment Center

The Deployment Center (Azure Portal → App Service → Deployment Center) is the central hub for configuring and monitoring deployments. From here you connect your source control, view deployment history, and troubleshoot failed deployments.

GitHub Actions CI/CD

The most popular and recommended approach for modern apps. When you connect GitHub in Deployment Center, Azure automatically generates a GitHub Actions workflow file in your repo.

How It Works

  1. Go to App Service → Deployment Center → Source: GitHub
  2. Authorise GitHub, select repo and branch
  3. Azure creates .github/workflows/azure-webapps.yml in your repo
  4. Every push to the selected branch triggers build + deploy
  5. Deployment status appears in GitHub Actions and Deployment Center
GitHub ActionsExample workflow for Node.js App Service deployment
name: Deploy to Azure App Service

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install and build
        run: |
          npm install
          npm run build

      - name: Deploy to Azure Web App
        uses: azure/webapps-deploy@v3
        with:
          app-name: mywebapp-2026
          publish-profile: ${{ secrets.AZURE_WEBAPP_PUBLISH_PROFILE }}
          package: ./dist

Azure DevOps Pipelines

For enterprise teams already using Azure DevOps, connect Azure Repos or GitHub in Deployment Center with Azure DevOps as the build provider. Azure DevOps Pipelines offer more control over build steps, approval gates, and release management.

Local Git

App Service can act as a Git remote — push code directly from your local machine to deploy. Good for individual developers or simple setups.

Azure CLI + GitConfigure and deploy via local Git
# Enable local Git deployment
az webapp deployment source config-local-git \
  --name mywebapp-2026 \
  --resource-group myRG

# Get the Git URL (from command output or portal)
# Format: https://@.scm.azurewebsites.net/.git

# Add as remote and push
git remote add azure https://mywebapp-2026.scm.azurewebsites.net/mywebapp-2026.git
git push azure main

ZIP Deploy

Package your application as a ZIP file and deploy via the Azure CLI or REST API. Fastest method for automated scripts and CI/CD pipelines without a full GitHub/DevOps setup.

Azure CLIDeploy a ZIP package
# Create ZIP of your app (example for Node.js)
zip -r myapp.zip . -x "node_modules/*" -x ".git/*"

# Deploy ZIP to App Service
az webapp deploy \
  --resource-group myRG \
  --name mywebapp-2026 \
  --src-path myapp.zip \
  --type zip

Container Deployment

Deploy a Docker container to App Service from Azure Container Registry (ACR), Docker Hub, or any private registry. App Service pulls the image and runs it — you define the container image + tag, and App Service handles the rest.

Azure CLIDeploy a container from ACR
# Create web app with container image
az webapp create \
  --name mywebapp-2026 \
  --resource-group myRG \
  --plan myAppServicePlan \
  --deployment-container-image-name myacr.azurecr.io/myapp:latest

# Configure continuous deployment (auto-redeploy when image updates)
az webapp deployment container config \
  --name mywebapp-2026 \
  --resource-group myRG \
  --enable-cd true

App Settings and Connection Strings

App Settings are environment variables injected into your app at runtime. They override any values in your config files — perfect for storing secrets, connection strings, and environment-specific settings without hardcoding them.

Azure CLISet App Settings
# Set environment variables
az webapp config appsettings set \
  --name mywebapp-2026 \
  --resource-group myRG \
  --settings \
    NODE_ENV=production \
    API_KEY=mysecretkey \
    DATABASE_URL=@Microsoft.KeyVault(SecretUri=https://myvault.vault.azure.net/secrets/dburl/)

# Set connection strings (shown separately in portal)
az webapp config connection-string set \
  --name mywebapp-2026 \
  --resource-group myRG \
  --connection-string-type SQLAzure \
  --settings "DefaultConnection=Server=myserver.database.windows.net;..."
💡
Reference Key Vault Secrets Instead of putting secrets directly in App Settings, reference Azure Key Vault secrets using the syntax: @Microsoft.KeyVault(SecretUri=...). This keeps secrets out of the portal and access logs.
