Azure Cloud Shell

What if you could run Azure CLI and PowerShell commands from any browser, on any device, anywhere in the world — without installing anything? That's exactly what Azure Cloud Shell does. It's a fully functional, authenticated, browser-based terminal built directly into the Azure Portal. For learners and professionals alike, it's the fastest way to get hands-on with Azure.

What is Azure Cloud Shell?

Azure Cloud Shell is an interactive, browser-based shell environment hosted by Microsoft. It gives you an authenticated terminal session running in the cloud — no installation, no configuration, and no need to manage credentials. Open a browser, go to the portal, click the terminal icon, and you're ready to run commands within seconds.

ℹ️
Key Point Cloud Shell runs on a temporary container hosted by Azure. Microsoft manages the underlying infrastructure — you just use the terminal. Every time you open Cloud Shell, you get a fresh container, but your files persist because they're stored in Azure File Storage (which you set up once).

How to Access Cloud Shell

There are three ways to open Cloud Shell:

Option 1 — From the Azure Portal

Click the terminal icon (>_) in the top navigation bar of the Azure Portal at portal.azure.com. This opens Cloud Shell in a panel at the bottom of the portal — you can use the portal and the terminal side by side.

Option 2 — Dedicated Cloud Shell URL

URL Dedicated Cloud Shell window 
https://shell.azure.com

This opens Cloud Shell in a full browser window — no portal chrome around it. Useful when you want a larger terminal workspace.

Option 3 — From Azure Documentation

Many Azure documentation pages have an "Open Cloud Shell" button embedded inline. Clicking it launches Cloud Shell with the relevant command pre-populated — great for following tutorials.

First-Time Setup

The very first time you open Cloud Shell, Azure will ask you to configure storage for persistent files. This is a one-time setup:

  1. Choose your Subscription
  2. Click Create storage (Azure creates a storage account and file share automatically)
  3. Wait ~30 seconds for the container to initialise
  4. Your shell prompt appears — you're ready
ℹ️
What Storage Gets Created? Azure creates a Storage Account (named something like cs[randomchars]) and a File Share inside it. Your Cloud Shell home directory (~/) is mapped to this file share. Anything you save there persists between sessions.
⚠️
Small Cost The storage account created for Cloud Shell incurs a small cost — typically less than ₹100/month for the file storage. It's minimal, but worth knowing. If you delete the storage account, your Cloud Shell files are gone and you'll need to set up storage again.

Bash vs PowerShell Mode

Cloud Shell supports two shells — you choose when you first set it up, and can switch anytime using the dropdown at the top of the shell:

Bash ModePowerShell Mode
ShellBash on Linux containerPowerShell 7 on Linux container
Azure toolAzure CLI (az)Azure PowerShell (Connect-AzAccount etc.)
Best forDevelopers, Linux users, CLI learnersWindows admins, PowerShell scripts
Scripting.sh shell scripts.ps1 PowerShell scripts
Both available?Azure CLI only in Bash mode by defaultBoth CLI and PS available in PS mode
💡
Both Are Available in Both Modes Even in Bash mode, you can run pwsh to switch to a PowerShell sub-shell. In PowerShell mode, you can run bash to switch to Bash. Cloud Shell is flexible — you're not locked into one shell.

Persistent Storage

Cloud Shell runs on a temporary container — when you close your session, the container is discarded. But your files survive because Cloud Shell mounts an Azure File Share to your home directory (~/clouddrive in Bash, or the home directory in PowerShell).

What Persists

  • Files in your home directory (~/) and ~/clouddrive
  • Shell history (bash_history or PowerShell history)
  • SSH keys stored in ~/.ssh/
  • Git credentials stored in ~/.gitconfig
  • Custom scripts you save to ~/

What Does NOT Persist

  • Installed packages (e.g., pip install or npm install -g — gone when session ends)
  • Environment variables set in the session
  • Any changes outside the home directory
Bash Save a script for reuse across sessions 
# Save a frequently used script to your home directory
# It will persist across all Cloud Shell sessions

cat > ~/deploy.sh << 'EOF'
#!/bin/bash
az group create --name rg-test --location centralindia
az vm create --resource-group rg-test --name myVM \
  --image Ubuntu2204 --size Standard_B1s \
  --admin-username azureuser --generate-ssh-keys
EOF

chmod +x ~/deploy.sh
echo "Script saved!"

The Cloud Shell Editor

Cloud Shell includes a built-in graphical code editor — type code . or code filename.sh to open it. It's based on VS Code's Monaco editor and gives you syntax highlighting, IntelliSense, and a proper file explorer.

Bash Open the Cloud Shell editor 
# Open a file in the editor
code myscript.sh

# Open the current directory in the editor
code .

Limitations

Cloud Shell is powerful, but it has some limitations you should know:

  • 20-minute timeout — If you don't type anything for 20 minutes, the session closes. Your files are safe, but you lose unsaved terminal state.
  • No root access — You can't run commands as root or install system-level packages permanently.
  • Single session — Cloud Shell supports one active session per user at a time.
  • No inbound connections — You can't host a web server or expose ports in Cloud Shell.
  • Requires storage — Cloud Shell requires an Azure Storage account. If your subscription doesn't support storage in your chosen region, setup will fail.
