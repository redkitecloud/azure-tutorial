Multi-Factor Authentication (MFA)

Multi-Factor Authentication requires users to provide two or more verification factors to sign in. Even if a password is compromised, an attacker still cannot access the account without the second factor. MFA is the single most effective control against account takeover attacks — Microsoft reports it blocks over 99.9% of automated attacks.

How MFA Works

Authentication factors fall into three categories — MFA requires at least two from different categories:

KnowledgeKnowPassword, PIN

Security Defaults

Security Defaults are pre-configured baseline security settings that Microsoft enables for free on all tenants. They enforce:

  • All users must register for MFA
  • Admins must use MFA on every sign-in
  • Legacy authentication protocols are blocked
  • All users must complete MFA when needed (risk-based)
ℹ️
Security Defaults vs Conditional Access Security Defaults are free and simple — enabled or disabled for the entire tenant. Conditional Access (P1 required) gives granular control — require MFA only for specific users, apps, locations, or risk levels. You cannot use both simultaneously.

Per-User MFA

The legacy method — enable MFA individually per user. Three states:

  • Disabled — MFA not required
  • Enabled — MFA required but user has not registered yet
  • Enforced — MFA required and user has completed registration
⚠️
Per-User MFA is Legacy Microsoft recommends using Conditional Access MFA instead of per-user MFA. Per-user MFA applies uniformly — Conditional Access lets you apply MFA contextually (e.g., only when signing in from outside the corporate network).

Conditional Access MFA (Recommended)

The modern, flexible approach. Use Conditional Access policies to require MFA based on conditions:

  • Require MFA when signing in from outside corporate network
  • Require MFA when accessing sensitive applications
  • Require MFA for all admin roles, always
  • Require MFA when sign-in risk is detected
  • Skip MFA for trusted locations (corporate office IP)

Passwordless Authentication

The future of authentication — remove passwords entirely:

  • Microsoft Authenticator — Approve sign-in via phone notification — no password needed
  • FIDO2 security keys — Hardware key that is both the possession and inherence factor
  • Windows Hello for Business — Face/fingerprint/PIN replaces password on Windows
