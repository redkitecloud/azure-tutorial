Just-in-Time (JIT) VM Access

Just-in-Time VM Access closes management ports (RDP port 3389 and SSH port 22) when not in use. Instead of keeping these ports open 24/7 — inviting brute force attacks — JIT only opens the port for a specific user from a specific IP for a limited time window. When time is up, the port closes automatically. It dramatically reduces the attack surface of your VMs.

The Problem JIT Solves

Without JIT, RDP (port 3389) and SSH (port 22) are typically open to the internet 24/7. This means:

  • Automated bots continuously scan for open RDP/SSH ports
  • Brute force and credential stuffing attacks run constantly
  • Even with strong passwords, exposure to zero-day vulnerabilities
  • Microsoft reports millions of RDP attacks per day against Azure VMs
⚠️
Open RDP to the Internet is High Severity Defender for Cloud flags open RDP (3389) or SSH (22) access to the internet as a high-severity recommendation. This is one of the most commonly exploited configurations in cloud environments.

How JIT Works

  1. Enable JIT — Defender for Cloud creates an NSG deny rule blocking all inbound traffic on management ports
  2. Request access — User requests access specifying source IP and time window (e.g., 3 hours)
  3. Approval — Request is automatically approved (or requires manual approval by an admin)
  4. Port opens — Defender temporarily adds an NSG allow rule for that specific user IP on that port
  5. Time expires — After the window, the allow rule is automatically removed and the port closes

Enabling JIT on a VM

Azure CLIEnable JIT access on a VM
# Enable JIT for a VM via Defender for Cloud
az security jit-policy create \
  --resource-group myRG \
  --location centralindia \
  --name default \
  --virtual-machines '[{
    "id": "/subscriptions//resourceGroups/myRG/providers/Microsoft.Compute/virtualMachines/myVM",
    "ports": [
      {
        "number": 22,
        "protocol": "TCP",
        "allowedSourceAddressPrefix": "*",
        "maxRequestAccessDuration": "PT3H"
      },
      {
        "number": 3389,
        "protocol": "TCP",
        "allowedSourceAddressPrefix": "*",
        "maxRequestAccessDuration": "PT3H"
      }
    ]
  }]'

Requesting JIT Access

Azure CLIRequest JIT access to a VM
# Request JIT access — opens SSH for 2 hours from your IP
az security jit-policy initiate \
  --resource-group myRG \
  --name default \
  --virtual-machines '[{
    "id": "/subscriptions//resourceGroups/myRG/providers/Microsoft.Compute/virtualMachines/myVM",
    "ports": [{
      "number": 22,
      "duration": "PT2H",
      "allowedSourceAddressPrefix": "203.0.113.10"
    }]
  }]'

JIT and NSG Rules

JIT manages NSG rules automatically:

  • When JIT is enabled — A high-priority deny rule is added blocking RDP/SSH from internet
  • When access is requested — A higher-priority allow rule is temporarily added for the specific source IP
  • When time expires — The allow rule is removed; the deny rule remains

The NSG changes are visible in the Azure Portal — you can see the temporary rules while access is active.

Audit Log

Every JIT access request is logged — who requested access, from what IP, for which port, and for how long. This provides a complete audit trail for compliance and security investigations. Logs are visible in Defender for Cloud and Azure Activity Log.

Requirements and Alternatives

JIT Requirements

  • Microsoft Defender for Servers plan must be enabled (paid)
  • VM must have an NSG attached
  • User needs specific permissions to request access

Azure Bastion — Alternative

Azure Bastion provides browser-based RDP/SSH access to VMs without any public IP or open ports. Traffic goes over SSL through the Azure portal — the VM never needs an internet-accessible RDP/SSH port at all. This is an even more secure alternative to JIT when public port access is not needed.
