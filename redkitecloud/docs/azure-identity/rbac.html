Azure Role-Based Access Control (RBAC)

Azure RBAC controls who can do what to which Azure resources. Instead of granting broad access, RBAC lets you assign the minimum permissions needed — a developer gets Contributor on their resource group but nothing else. RBAC is one of the most heavily tested topics in AZ-104 and understanding it deeply is essential for every Azure professional.

RBAC Concepts

A role assignment has three components:

ComponentDescriptionExample
Security PrincipalWho gets access — user, group, service principal, or managed identitypriya@contoso.com, Developers group
Role DefinitionWhat they can do — a collection of permissions (actions)Contributor, Virtual Machine Operator
ScopeWhere the access appliesResource group, subscription

Scope Hierarchy

RBAC scope follows the Azure resource hierarchy. A role assigned at a parent scope is inherited by all child scopes:

Scope LevelApplies To
Management GroupAll subscriptions under the management group
SubscriptionAll resource groups and resources in the subscription
Resource GroupAll resources in the resource group
ResourceOnly that specific resource
ℹ️
Inheritance A user assigned Contributor at the subscription level automatically has Contributor on all resource groups and resources within that subscription. Assign at the highest scope that makes sense — use resource group scope to limit exposure.

Key Built-in Roles

RoleCan DoCannot Do
OwnerEverything — create, delete, manage, assign rolesNothing restricted
ContributorCreate and manage all resourcesAssign roles to others, manage access
ReaderView all resourcesMake any changes
User Access AdministratorManage user access to Azure resourcesCreate or manage resources
Virtual Machine ContributorManage VMsManage VNet or storage the VM uses
Storage Blob Data ContributorRead, write, delete blob dataManage storage account settings
💡
Owner vs Contributor The key difference: Owner can assign RBAC roles to others; Contributor cannot. If you want a user to manage resources but not grant access to anyone else, use Contributor.

Assigning Roles

Azure CLIAssign and manage roles
# Assign Contributor role at resource group scope
az role assignment create \
  --assignee priya@contoso.com \
  --role Contributor \
  --resource-group myRG

# Assign Reader at subscription scope
az role assignment create \
  --assignee priya@contoso.com \
  --role Reader \
  --scope /subscriptions/

# List role assignments for a user
az role assignment list \
  --assignee priya@contoso.com \
  --output table

# Remove a role assignment
az role assignment delete \
  --assignee priya@contoso.com \
  --role Contributor \
  --resource-group myRG

Custom Roles

When built-in roles do not fit, create custom roles with exactly the permissions needed:

JSONCustom role definition — VM Start/Stop only
{
  "Name": "VM Operator",
  "Description": "Can start and stop VMs but not create or delete",
  "Actions": [
    "Microsoft.Compute/virtualMachines/start/action",
    "Microsoft.Compute/virtualMachines/deallocate/action",
    "Microsoft.Compute/virtualMachines/restart/action",
    "Microsoft.Compute/virtualMachines/read"
  ],
  "NotActions": [],
  "AssignableScopes": [
    "/subscriptions/"
  ]
}

Deny Assignments

Deny assignments block specific actions — even if a role assignment would otherwise allow them. A deny assignment overrides any allow. Currently, deny assignments can only be created by Azure Blueprints and Managed Applications — not manually by users.

RBAC vs Entra ID Roles

Azure RBACEntra ID Roles
Controls access toAzure resources (VMs, storage, networks)Entra ID objects (users, groups, apps)
ScopeManagement group, subscription, resource group, resourceTenant-wide (or admin unit)
ExamplesContributor, Reader, VM ContributorGlobal Administrator, User Administrator, Billing Administrator
Assigned viaAzure Portal / CLI / IAM bladeEntra ID portal / roles blade
💡
AZ-104 Exam Tip This is very heavily tested. Know Owner vs Contributor (Owner can assign roles, Contributor cannot). Know that role assignments are inherited downward through the scope hierarchy. Know that deny assignments override allow assignments. Know the difference between Azure RBAC (resource access) and Entra ID roles (identity access).
