Microsoft Entra ID (Azure Active Directory)

Microsoft Entra ID — formerly Azure Active Directory (Azure AD) — is Microsoft's cloud-based identity and access management service. It is the foundation of security in Azure: every user, application, and service that interacts with Azure authenticates through Entra ID. Understanding it is the single most important prerequisite for working with Azure security.

What is Microsoft Entra ID?

Microsoft Entra ID is a cloud-based Identity and Access Management (IAM) service. It handles:

  • Authentication — Verify who you are (username + password + MFA)
  • Authorisation — What you are allowed to do (RBAC, permissions)
  • Single Sign-On (SSO) — Sign in once, access thousands of apps
  • Application management — Register and manage app identities
  • Device management — Register and manage devices (Intune integration)
ℹ️
The Name Change Azure Active Directory (Azure AD) was renamed to Microsoft Entra ID in 2023. The functionality is identical — only the name changed. Exam questions may still use "Azure AD" — treat them as the same service.

Tenants and Directories

A tenant is a dedicated instance of Entra ID that an organisation receives when signing up for Microsoft cloud services. Each tenant:

  • Has a unique tenant ID (GUID)
  • Has a default domain: contoso.onmicrosoft.com
  • Can have custom domains added: contoso.com
  • Is completely isolated from other tenants
  • Contains all the organisation's users, groups, and applications
💡
One Tenant per Organisation Most organisations have a single Entra ID tenant. Large enterprises may have multiple tenants (acquired companies, dev/prod separation) — these can be connected via B2B collaboration.

Entra ID vs On-Premises Active Directory

Entra ID (Cloud)Active Directory DS (On-premises)
Primary protocolOAuth 2.0, OIDC, SAMLKerberos, NTLM, LDAP
StructureFlat — no OUs or GPOsHierarchical — OUs, GPOs, forests
Domain joinEntra Join (cloud), Hybrid JoinTraditional domain join
Group PolicyNo GPO — use Intune/Conditional AccessFull GPO support
QueryingREST API / Microsoft GraphLDAP
⚠️
Entra ID is NOT a cloud version of AD DS A common misconception. Entra ID uses completely different protocols and has no OUs, Group Policy, or LDAP. If you need traditional AD features in Azure, use Azure Active Directory Domain Services (Entra Domain Services).

Entra ID Editions

EditionKey Features
FreeBasic user/group management, SSO for 10 apps, MFA for admins
P1Conditional Access, self-service password reset, hybrid identity, MFA for all users
P2P1 + Identity Protection (risk-based Conditional Access), Privileged Identity Management (PIM)

Authentication Protocols

  • OAuth 2.0 — Authorisation framework — grants apps access to resources on behalf of users
  • OpenID Connect (OIDC) — Authentication layer on top of OAuth 2.0 — proves who the user is
  • SAML 2.0 — Enterprise SSO standard — used for integrating legacy enterprise apps
  • WS-Federation — Older federation protocol — used for legacy Microsoft apps

Hybrid Identity

Most enterprises have both on-premises AD and Entra ID. Microsoft Entra Connect (formerly Azure AD Connect) synchronises identities between them:

  • Users created in on-premises AD are synced to Entra ID automatically
  • Password hash synchronisation — users use the same password for cloud and on-premises
  • Pass-through authentication — authentication happens against on-premises AD
  • Federation (ADFS) — on-premises ADFS handles all authentication
💡
AZ-104 Exam Tip Know that Entra ID is cloud IAM — not a cloud version of AD DS. Know the four identity types (user, group, service principal, managed identity). Know the difference between system-assigned and user-assigned managed identities. Know P1 adds Conditional Access and P2 adds PIM and Identity Protection.
