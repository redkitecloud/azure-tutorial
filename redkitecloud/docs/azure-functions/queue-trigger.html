Queue Trigger

The Queue trigger fires your function whenever a new message arrives in an Azure Storage Queue. It's the foundation of scalable, decoupled architectures — one service enqueues a message, your function processes it independently. Failed messages are automatically retried, and poison messages are moved to a dead-letter queue automatically.

How the Queue Trigger Works

Azure Functions polls the storage queue for new messages. When a message arrives:

  1. Functions detects the message and makes it invisible to other consumers (visibility timeout)
  2. Your function code executes with the message content
  3. If function completes successfully — message is deleted from the queue
  4. If function throws an exception — message becomes visible again for retry
PythonBasic Queue trigger
import azure.functions as func
import logging
import json

app = func.FunctionApp()

@app.queue_trigger(arg_name="msg",
                   queue_name="orders",
                   connection="AzureWebJobsStorage")
def process_order(msg: func.QueueMessage) -> None:
    # Get message content
    order = json.loads(msg.get_body().decode("utf-8"))

    logging.info(f"Processing order {order['orderId']} for {order['customer']}")

    # Process the order...
    # If this throws an exception, the message is retried

Message Format and Limits

  • Max message size — 64 KB
  • Format — Plain text, JSON, or base64-encoded binary
  • Max TTL — 7 days by default (configurable up to infinite)
  • Visibility timeout — How long message is hidden while being processed (default: based on queue settings)

Retry Behaviour

If your function throws an exception, the message becomes visible again on the queue and will be retried. The dequeue_count property tracks how many times the message has been dequeued:

PythonCheck dequeue count for retry logic
@app.queue_trigger(arg_name="msg", queue_name="orders",
                   connection="AzureWebJobsStorage")
def process_order(msg: func.QueueMessage) -> None:
    dequeue_count = msg.dequeue_count
    logging.info(f"Processing attempt #{dequeue_count}")

    if dequeue_count > 3:
        logging.warning("Message has failed 3 times — check for data issues")

    # Process...

Poison Message Handling

After 5 failed attempts (default), Azure Functions automatically moves the message to a poison message queue named {queue-name}-poison. This prevents a single bad message from blocking the entire queue.

  • Poison queue name: orders-poison (for a queue named orders)
  • You should monitor the poison queue and alert on messages arriving there
  • Investigate and reprocess or discard poison messages manually
💡
Monitor the Poison Queue Set up an alert or another function that monitors the poison queue. A message landing there means your processing logic failed 5 times — likely a data issue or bug that needs investigation.

Queue Output Binding

Write messages to a queue from any function — not just queue-triggered ones:

PythonHTTP function that enqueues a job
@app.route(route="submit-order", methods=["POST"])
@app.queue_output(arg_name="orderQueue",
                  queue_name="orders",
                  connection="AzureWebJobsStorage")
def submit_order(req: func.HttpRequest,
                 orderQueue: func.Out[str]) -> func.HttpResponse:
    order = req.get_json()
    # Enqueue for async processing
    orderQueue.set(json.dumps(order))
    return func.HttpResponse(
        json.dumps({"status": "queued", "orderId": order["orderId"]}),
        mimetype="application/json",
        status_code=202   # 202 Accepted — processing will happen async
    )

Scaling Behaviour

Queue triggers scale based on queue depth — the number of messages waiting:

  • 1 instance processes up to 16 messages concurrently (configurable)
  • As queue depth grows, more instances are added automatically
  • Max instances: 200 per function app (Consumption plan)
  • Scales to zero when queue is empty

Real Example — Order Processing

PythonFull order processing pipeline
@app.queue_trigger(arg_name="msg", queue_name="orders",
                   connection="AzureWebJobsStorage")
@app.queue_output(arg_name="notifyQueue", queue_name="notifications",
                  connection="AzureWebJobsStorage")
def process_order(msg: func.QueueMessage,
                  notifyQueue: func.Out[str]) -> None:
    order = json.loads(msg.get_body().decode("utf-8"))
    order_id = order["orderId"]

    # 1. Reserve inventory
    reserve_inventory(order)

    # 2. Charge payment
    charge_payment(order)

    # 3. Enqueue notification for customer
    notification = {"type": "order_confirmed", "orderId": order_id,
                    "email": order["email"]}
    notifyQueue.set(json.dumps(notification))

    logging.info(f"Order {order_id} processed successfully")
💡
AZ-204 Exam Tip Know that after 5 failed retries, messages move to the {queue}-poison queue. Know max Storage Queue message size is 64 KB. Know that scaling is based on queue depth. Know that Storage Queue is simpler/cheaper than Service Bus but lacks ordering, larger messages, and pub/sub.
