Timer Trigger — Scheduled Jobs with Azure Functions

The Timer trigger lets you run Azure Functions on a schedule — like a cloud cron job. No always-on server required. Need to send a daily report at 8am, clean up old records every Sunday, or ping an API every 5 minutes? Timer triggers handle all of this with a single cron expression, and you pay only for the execution time.

NCRONTAB Cron Format

Azure Functions uses NCRONTAB — a 6-field cron expression (unlike the standard 5-field Unix cron). The extra field is for seconds:

FormatNCRONTAB expression — 6 fields
{second} {minute} {hour} {day} {month} {day-of-week}

Examples:
0 0 * * * *        Every hour (at minute 0, second 0)
0 */5 * * * *      Every 5 minutes
0 0 8 * * *        Every day at 8:00 AM
0 0 8 * * 1-5      Weekdays at 8:00 AM (1=Monday, 5=Friday)
0 0 0 1 * *        First day of every month at midnight
0 0 9 * * 1        Every Monday at 9:00 AM
ℹ️
6 Fields, Not 5 Standard Unix cron has 5 fields (minute to day-of-week). Azure Functions NCRONTAB has 6 fields — the first field is seconds. Don't forget the leading second field or your schedule will be off by one position.

The TimerInfo Object

PythonTimer trigger function
import azure.functions as func
import logging
from datetime import datetime

app = func.FunctionApp()

@app.timer_trigger(schedule="0 0 8 * * *", arg_name="timer", run_on_startup=False)
def daily_report(timer: func.TimerRequest) -> None:
    if timer.past_due:
        logging.warning("Timer is running late — was scheduled earlier")

    logging.info(f"Daily report triggered at {datetime.utcnow()}")

    # Your scheduled job logic here
    # e.g., generate report, send email, clean up old records

The TimerRequest object provides:

  • timer.past_due — True if the function is running later than scheduled (e.g., after a cold start)
  • timer.schedule_status — Object with last, next, and last_updated timestamps

Timezone Configuration

By default, Timer triggers run in UTC. To run in a specific timezone, set the WEBSITE_TIME_ZONE app setting:

Azure CLISet timezone for timer trigger
# Run schedule in India Standard Time (UTC+5:30)
az functionapp config appsettings set \
  --name myfunctionapp-2026 \
  --resource-group myRG \
  --settings WEBSITE_TIME_ZONE="India Standard Time"

# Other common timezones:
# "Eastern Standard Time"    (US Eastern, UTC-5/-4)
# "UTC"                      (always UTC)
# "GMT Standard Time"        (UK)
💡
IST Note For India Standard Time (UTC+5:30), set WEBSITE_TIME_ZONE=India Standard Time. A schedule of 0 0 8 * * * will then fire at 8:00 AM IST (2:30 AM UTC) — useful for morning reports and business-hours tasks.

Missed Schedules

If the Function App is down during a scheduled execution (e.g., redeployment, scaling), the schedule is missed. Azure does not automatically run missed executions when the app comes back up. Check timer.past_due to detect if the current run is late and handle accordingly.

RunOnStartup

Setting run_on_startup=True makes the function run immediately when the Function App starts — in addition to its scheduled runs. Useful for testing but avoid in production — every cold start and redeployment will trigger the function unexpectedly.

Real-World Examples

PythonNightly database cleanup
@app.timer_trigger(schedule="0 0 2 * * *", arg_name="timer")  # 2am daily
def cleanup_old_records(timer: func.TimerRequest) -> None:
    """Delete records older than 90 days"""
    import pyodbc
    conn = pyodbc.connect(os.environ["SQL_CONNECTION"])
    cursor = conn.cursor()
    cursor.execute("DELETE FROM logs WHERE created_at < DATEADD(day, -90, GETDATE())")
    deleted = cursor.rowcount
    conn.commit()
    logging.info(f"Cleanup complete: deleted {deleted} old log records")
💡
AZ-204 Exam Tip Know that NCRONTAB has 6 fields (seconds first). Know that schedules run in UTC by default — use WEBSITE_TIME_ZONE to change. Know that past_due indicates a late execution. Know that RunOnStartup should not be used in production.
