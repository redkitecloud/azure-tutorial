Azure Functions Hosting Plans

Where your Functions run determines how they scale, what features are available, and what you pay. Azure Functions offers three hosting plans — Consumption (pure serverless), Premium (always warm, VNet), and Dedicated (run on App Service Plan). Choosing the wrong plan is one of the most common mistakes in Functions deployments.

Consumption Plan

The classic serverless plan — scales to zero, pay per execution. Microsoft manages all scaling automatically.

Key Characteristics

  • Scales to zero — no instances when not running, no compute cost when idle
  • Auto-scale — scales from 0 to 200 instances automatically
  • Cold starts — first execution after idle has startup delay (seconds)
  • Max execution timeout — 5 minutes (default), up to 10 minutes
  • No VNet integration — apps run on shared infrastructure
  • Max memory — 1.5 GB per instance

Billing

  • Per execution: first 1 million executions/month free, then ~₹0.17 per million
  • Per GB-second: first 400,000 GB-seconds free, then ~₹0.014 per GB-second
💡
Best for sporadic workloads If your function runs a few hundred thousand times per month and can tolerate occasional cold starts, Consumption is the cheapest option — often nearly free within the generous free tier.

Premium Plan

The Premium plan eliminates cold starts by keeping at least one instance always warm — while still scaling out automatically for load spikes.

Key Characteristics

  • Pre-warmed instances — configurable minimum of 1+ always-warm instances (no cold starts)
  • VNet Integration — connect to private VNets for database/service access
  • Unlimited execution duration — no 10-minute timeout limit
  • Larger instances — up to 14 GB memory, 4 vCPU
  • VNET-triggered scaling — scale based on Service Bus, Event Hubs
  • Up to 100 instances — scale out limit

Billing

Charged per vCPU-second and GB-second — continuously for pre-warmed instances plus additional instances during scale-out. Minimum monthly cost: ~₹5,000–8,000 (for EP1, 1 always-warm instance).

Dedicated (App Service) Plan

Run Functions on a regular App Service Plan — the same VMs that host Web Apps. Functions share the plan's compute with other apps.

Key Characteristics

  • Always on — no cold starts, always running
  • Predictable cost — fixed hourly rate regardless of executions
  • Manual or auto-scaling — same as App Service scaling
  • Unlimited execution duration — no timeout limit
  • Share plan with Web Apps — put functions alongside your web app
ℹ️
Use Always On Setting On Dedicated plans, enable Always On to prevent the Functions host from going idle. Without it, functions may have cold start delays similar to Consumption plan.

Flex Consumption Plan

A newer plan (preview/GA depending on region) that combines Consumption-style per-execution billing with configurable concurrency, faster cold starts, and VNet support — addressing many Consumption plan limitations without Premium plan costs.
